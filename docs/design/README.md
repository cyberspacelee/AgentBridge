# AgentBridge 设计基线

版本：2.0，2026-09-08。状态：Agent 管理前后端与四个适配器已实现，验证范围见 [交付与验收](DELIVERY.md)。优先阅读 [Agent 管理统一设计](AGENTS.md)，其配置、生命周期、接口与连续对话约定替代旧版双引擎约定。

交付目标是一套完整的多 Agent 网关及前端工作台：OpenCode、Pi、Codex CLI 与 Grok Build 四个真实适配器、赛题协议、任务执行控制、办公工具、持久化、任务页面、整体观测、异常恢复和 Windows 交付。实施分阶段组织，但完成标准按完整范围验收，不能在某一条演示链路跑通后宣布完成。

## 已有约束

- Windows 10/11 为验收平台，本地开发兼容 Linux。
- Agent Engine 为 OpenCode、Pi、Codex CLI、Grok Build；通过适配器接入。
- 一个网关实例管理四个 Agent，独立动态启停，默认 Agent 与已启用 Agent 分离。
- 一个前端应用，包含任务、Agents、观测与系统设置。
- React + TypeScript + Vite；shadcn/ui 选择 Base UI，使用 Tailwind CSS 4，禁止引入 Radix。
- 前后端使用 pnpm workspace，版本固定为 10.33.2，共用 code/pnpm-lock.yaml。
- 先确定设计、统一术语与领域模型，再开始业务实现；完整实现前后端。

## 本次设计决策

以下是设计基线的具体选择，审阅后作为实现约束。

| 编号 | 决策 | 依据与影响 |
| --- | --- | --- |
| ADR-01 | 后端采用 TypeScript + Fastify，交付目标 Node.js 24 LTS | 前后端契约可复用，便于事件和引擎协议集成；Node.js 精确补丁版本在 Windows 验证时锁定 |
| ADR-02 | 模块化单体，网关与静态前端同源部署 | 会话、事件与控制共享同一执行入口；引擎进程保持隔离 |
| ADR-03 | Task 是 Session 的用户视图；Run 是执行单位 | 消除两套任务状态机，统计和取消都有明确对象 |
| ADR-04 | Domain 只定义业务语义；Application 编排 I/O | HTTP、数据库与引擎协议均不能进入纯领域模块 |
| ADR-05 | SQLite 为默认状态存储，内存存储只用于测试或显式评测配置 | 重启后保留历史、幂等结果和审计；不因赛题允许降级而默认丢失工作记录 |
| ADR-06 | 状态、相关消息和待发布事件在同一事务提交 | 避免页面收到完成事件但读取不到完成快照 |
| ADR-07 | 同 Session 串行，全局有界并发 | 工作目录上下文与取消可控；接收配额包括已接受的排队项 |
| ADR-08 | OpenCode 使用 HTTP/SSE，Pi 使用 RPC，Codex 使用 app-server，Grok 使用 ACP | 传输差异局限在适配层；版本和进程归属可追踪 |
| ADR-09 | HTTP 请求成功、Run 完成、业务验收通过分别记录 | 不将 202、idle 或模型正常结束当成业务通过 |
| ADR-10 | 本地有界观测 + Prometheus 指标 + OpenTelemetry 可选导出 | 沙箱独立可运行；部署有现成观测平台时可接入 |
| ADR-11 | 应用 SSE 支持保留窗口内回放，缺口回到快照 | 页面刷新、断线和事件重复有明确恢复语义 |
| ADR-12 | 整轮任务不自动重放；重启后未完成轮次明确失败 | 文件修改、删除、消息发送无法由网关保证 exactly-once |

新增持久化和回放属于本次完整方案的范围扩展。它们不意味着建设集群调度、跨引擎迁移或完整事件溯源系统。

## 完整交付的范围

1. 评测与应用两组 API、完整会话生命周期、SSE、权限与反问处理。
2. Run 排队、限额、超时、取消、删除、异常退出和受控重启。
3. 四个 Agent 真实接入，双向 ID 映射、完整轨迹、指定目录与模型、工具和交互回复。
4. 任务创建、搜索、筛选、分页、追加要求、执行查看、交互回复、取消、删除及文件下载预览。
5. 网关整体指标、引擎工具、资源连接、异常日志与执行调用链；指标口径和缺失状态正确。
6. 历史记录、幂等提交与重启恢复、事件回放与保留策略；旧配置和数据库不自动迁移。
7. 通过分配的 Skill/MCP 接入办公、文件、搜索等能力；真实样本与外部应用单独验收。
8. Windows 安装与无人工启动、契约测试、真实引擎测试、浏览器测试及打包说明。

本次部署边界为单可信环境、单网关实例。SSO、多租户 RBAC、集群高可用、计费结算、跨引擎上下文迁移未出现在当前需求中，不自动扩张为本次交付承诺。访问控制在部署层落实；如转为多用户产品，应先扩展身份和授权领域。

默认只绑定 loopback 地址。需要远程访问时，部署层必须提供经过验证的身份与访问控制，并同步保护业务 API、事件、产物及观测入口；不能将裸露的命令执行网关直接绑定公共网络作为企业部署方案。

## 设计与开发的先后关系

设计审阅检查术语、领域不变量、接口、页面与验收的一致性。当前管理设计已确认并实现，后续修改须同步代码、契约、文档与验证证据。

完成状态与尚需目标环境验证的项目以 [交付与验收](DELIVERY.md) 为准。运行时安装更新单独标记为方案分析，不能把动态启停写成已实现下载安装。

外部协议 schema 到位后，将 CONTRACTS 中待核对项变成独立 schema 与真实样例，再实现对应序列化。方案变更用 ADR 编号记录原因与影响，不在实现时静默删减范围。

## 资料依据

- [OpenCode Server](https://opencode.ai/docs/server/) 提供 HTTP、SSE 与 OpenAPI 能力，需以锁定版本验证实际返回结构。
- [Pi RPC](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md) 定义 JSONL、命令应答与异步事件；命令接受不等于执行完成。
- [SQLite 原子提交](https://www.sqlite.org/atomiccommit.html) 支持将相关状态写入一个事务；网关到外部引擎的操作仍不具备跨系统原子性。
- [Fastify 校验与序列化](https://fastify.dev/docs/latest/Reference/Validation-and-Serialization/) 支持基于 schema 的边界校验；协议 schema 属于项目源码，不接受请求动态提供。
