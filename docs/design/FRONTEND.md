# 前端信息架构与交互设计

目标是可连续使用的任务工作台和网关观测系统。技术基线固定为 React、TypeScript、Vite、shadcn/ui Base UI 和 Tailwind CSS 4。组件通过官方 CLI 按需引入，不混用 Radix。

基础组件选型、封装边界与整改验收见 [UI 组件统一规范](UI_COMPONENTS.md)。

视觉与 Agent 组件的统一规则见 [design.md](../../design.md)，实施基线与进度见 [UI 整改记录](UI_REMEDIATION.md)。本文负责信息架构与行为；涉及颜色、字体、布局尺寸、消息 / Tool 结果呈现时以 design.md 为准。2026-09-06 已落地本轮视觉与 Agent UI 整改，检查证据及未覆盖的外部验收见 [验收记录](../../code/artifacts/ui/README.md)。

## 1. 应用结构

```text
AgentBridge
  会话 /tasks
    新会话：直接输入，选择默认或其他就绪 Agent
    历史会话：侧栏（窄屏 Sheet），支持搜索、筛选和游标分页
    会话详情 /tasks/:sessionId
      执行过程
      结果与文件
      运行诊断：链接到观测中的同一 Run
  Agent 管理 /agents
    Agent 详情 /agents/:id：模型、Skills、MCP、运行
  共享资源 /agents/resources：模型连接、Skills、MCP
  系统信息 /settings
  运行观测 /observability
    运行概览
    引擎与资源
    工具与用量
    异常与调用链
```

一个应用、一次部署；刷新深层链接可访问。页面共享左侧主导航、连接状态和主题控件。窄屏将导航收进可访问菜单，主工作区保留足够宽度。

搜索、筛选、分页、Agent／资源／观测标签和时间范围写入 URL。任务草稿只保存在当前页面状态，默认不将 prompt 和服务端路径写入 localStorage。Agent 引用与策略草稿按实例保存在 sessionStorage，切页和刷新可恢复，同字段远端冲突须明确处理；密钥表单不写入浏览器存储。主题偏好可持久化。

Agent 配置流程与状态规则统一见 design.md 的“页面职责与交互约束”。保存保持 revision 乐观并发校验，应用／启用接收 202 后等待 Agent 快照确认；已有执行或排队任务时，生命周期操作明确告知影响。资源页按来源 Agent 返回对应标签。没有就绪 Agent 时，任务页显示配置入口，不能仅留下禁用按钮。

## 2. 会话

主工作区为新会话输入或当前连续对话。历史会话位于独立滚动侧栏，显示标题、Agent 与状态；窄屏通过 Sheet 打开。搜索、状态筛选和游标分页沿用应用 API。SSE 自动更新，失败时提供明确的重新加载按钮。

### 新建会话

直接展示 InputGroup 消息输入、Agent Select 与必填工作目录；默认选择就绪的默认 Agent，无默认可用时选择第一个就绪 Agent。标题、模型与交互策略放在 Collapsible 内，默认继承 Agent 的已应用配置；模型目录仅含已授权引用。没有可用 Agent 提供配置入口。目录、模型和提交失败显示可恢复的 Alert，不能把错误藏在折叠设置内。

第一次提交生成 submissionId，同一草稿的网络重试复用该 ID。内容修改属于新提交，应生成新 ID。超时不能直接显示“创建失败并再发一次”，先通过 submission 查询接收结果。

收到 AcceptedRun 后进入详情；即使 Run 已经极快完成，也从服务端快照显示真实状态。页面跳转不会取消已经接受的执行。

## 3. 任务详情

顶部显示标题、状态、引擎、当前模型、工作目录、接收时间与执行耗时；操作包含取消和删除。删除需明确确认其范围：删除任务记录，保留工作目录文件。

桌面为主执行区和可收起信息栏，窄屏改为单列。默认展示完整连续对话，以 Run 状态与耗时分隔；执行筛选保留在 URL，供定位历史执行和诊断使用。

消息使用官方 Message/Bubble，思考内容通过 Collapsible 展示；按稳定 ID 更新，工具调用可展开输入、输出、错误及耗时。累计工具输出覆盖展示，不能重复拼接。大输出显示截断与受控文件下载位置；文本不能撑开整个页面。

自动滚动仅在用户已位于底部时执行；用户上翻历史后保持位置，并显示新进度入口。追加要求不会清空旧轮次；排队轮次与当前执行清晰区分。

底部提交框用于追加 Run，支持明确提交、输入校验和幂等恢复。Session unavailable/deleting 时禁用提交并解释原因；不能把历史会话自动换引擎继续。

### 权限与问题

待处理交互在对应轮次就地展示。权限提供 once、always、reject；问题通过官方 Questionnaire 根据 schema 渲染逐题的单选、多选或文本输入。提交期间保留 replying 状态。

自动回复后保留处理结果与时间；人工抢占失败刷新最新状态。Run 终止后所有未处理交互显示已过期，不保留仍可点击的确认按钮。

### 取消与删除

取消请求提交后显示 stopping，等待服务端确认。请求失败时重新读取实际状态；不得直接将页面乐观改为 cancelled。

删除进行中禁止追加，失败显示清理原因和可重试入口。已被另一页面删除时返回列表并清理该 Session 的缓存和订阅，避免继续显示可执行按钮。

### 结果与文件

展示最终回答、文件名称、类型、大小、来源轮次、可用性与检查范围。下载走 artifactId，不拼接任意服务端路径。

文本预览有大小上限，默认按纯文本展示；Markdown 渲染禁止原始 HTML 或经过净化。Office 文件提供下载及真实结构检查结果，不承诺浏览器原生编辑 Office。

文件丢失、被修改、越界、未检查和检查失败有不同状态。Agent 执行完成与某项文件检查通过分别展示，不能显示一个没有依据的总体“验收通过”。

## 4. 网关观测

共享控件包含时间范围、自动刷新开关、手动刷新、最新采集时间和数据新鲜度。四个标签复用同一查询时间范围。

| 标签 | 必须展示 | 必须支持的定位操作 |
| --- | --- | --- |
| 运行概览 | live/ready、接收与终态速率、执行成功率、失败/超时/取消、队列与耗时趋势、持续异常 | 从错误或异常进入筛选后的 Run |
| 引擎与资源 | 启用引擎和版本、进程/就绪/重启、网关 CPU/RSS/heap/事件循环、可得的引擎进程采样、并发配额、存储、SSE/背压/上游连接 | 按引擎阶段、资源饱和或连接错误定位时间段与失败轮次 |
| 工具与用量 | 原生调用与工具耗时、工具失败、实际 token/cost、用量覆盖范围 | 按工具进入失败轮次，区分已报告与缺失用量 |
| 异常与调用链 | 时间、阶段、类别过滤，日志、Run spans、工具跨度和错误原因 | 跳到任务详情指定 Run，并可返回原观测筛选 |

观测以少量紧凑指标、趋势图和表格组织，页面分区不堆成卡片墙。图表采用成熟库，数据来自真实接口；图表提供单位、图例、时间范围以及表格或可读摘要。

unknown、unsupported、not_collected、stale、empty 与真实零值分别展示。没有样本时成功率不为 100%，没有费用时不为 0 元。同一实例可以启用多个 Agent；各自健康、排队和配置应用状态独立展示，观测按 engineId 筛选。

运行诊断只显示真实可测阶段。trace 过期或被采样时说明覆盖范围；task 仍可查看时保留跳转。日志默认不显示密钥或全部 prompt。

## 5. 数据与状态归属

| 状态 | 归属 |
| --- | --- |
| Session、Run、Message、Interaction、Artifact | 后端持久化快照和已提交事件 |
| 筛选、当前标签、时间范围、历史轮次选择 | URL |
| 表单草稿、展开工具行、滚动位置 | 当前页面 |
| 主题 | ThemeProvider 与本地偏好 |
| SSE 连接与快照恢复 | 应用级数据模块，一条共享连接 |

前端不使用 effects 分别建立多个同义事件连接。事件订阅有卸载清理；断线进入有界退避，恢复严格遵循 CONTRACTS 中的游标与快照流程。HTTP 和事件不能各维护一份独立状态。

HTTP 客户端统一处理 schema、错误码、requestId、超时和 AbortSignal。组件取消查询不取消服务端 Run。数据缓存库与路由库在业务实现时按实际需求选定并锁版本，不让领域模块依赖前端缓存对象。

## 6. UI 与可访问性验收

- 复用 shadcn Base UI 的组合 API，Dialog 有 Title/Description，关闭后恢复焦点。
- 图标操作有可访问名称与必要 Tooltip；危险命令与导航链接保持正确语义。
- 表单错误关联输入，待提交状态不会改变按钮尺寸或导致布局跳动。
- 全部重要操作可用键盘完成；状态更新不抢焦点，大量实时文本不逐字播报。
- 浅深色使用语义 token；状态不只依赖颜色，图表色可区分且有文字图例。
- 360px、768px、1440px 视口检查长中文、长路径、宽表格及弹层，页面不出现非预期横向滚动。
- 加载、失败、无权限、空数据、断线、重启、任务被删除和文件失效均有可验证页面状态。
- Playwright 验证任务提交、过程更新、交互回复、取消、刷新恢复、下载和观测跳转；保存桌面与窄屏截图作为验收证据。

## 7. 前后端闭环要求

任何可见按钮都必须对应真实用例及失败处理。任何可见指标都必须对应采集点、统计口径与真实查询。设计中的路由、数据状态和操作全部实现并验证后，才能将前端标记为完成；静态演示数据只允许测试环境显式使用。
