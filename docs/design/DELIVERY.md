## 关键验证集

### 领域与事务

- 同会话双提交和跨会话并发，不超配额、不双启动、不串目录。
- 同提交键并发、响应丢失、重启、删除后重试，都不静默创建第二轮。
- 完成与取消/超时竞争，终态与用量只入账一次；queued 超时不启动引擎。
- 自动交互与人工回复竞争，未知传输结果不会重复发送授权。
- 状态事务回滚不发完成事件；磁盘失败不返回假 202/204。
- 重启保留已完成历史；旧非终态明确失败，旧绑定不可复用。

### 原生协议与故障

- OpenCode 全局 SSE 多目录过滤、part delta/累计更新、流断线最终补齐、工具多轮与权限问题。
- Pi UTF-8 分块、LF/CRLF、半条 JSON、有效字符串中的 Unicode 分隔符、超大或非法记录。
- Pi 命令接受与最终收敛分离，自动重试或压缩不被误判为 Run 完成；依据锁定版本事件验证。
- 共享进程退出同时收尾受影响 Run；单会话 Pi 退出不影响其他会话。
- 取消超时强停拥有的进程树；PID 重用或不属于本网关的进程不得误杀。
- 两引擎真实指定 provider/model、路径读写与工具调用；配置缺失明确失败。

### 浏览器与观测

- 双击提交、请求超时、刷新和多标签页交互均与服务端一致。
- 快照与事件交错、重复事件、回放缺口、重启、另一页面删除任务。
- 取消尚未确认、交互已自动处理、文件已修改/丢失时界面不误导。
- 202 接收成功但 Run 失败时，HTTP 与运行指标分别正确。
- 费用缺失、零分母、保留期外 trace、计数器重置、空历史有明确显示。
- 不同尺寸截图无文本遮挡，键盘可操作，下载产物内容可验证。

## 评测报告格式

每条结果至少包含 caseId、engineId、引擎版本、模型引用、Windows 版本、开始/结束时间、sessionId/runId、RunOutcome、业务验证结果、产物摘要、轨迹位置与失败分类。

执行完成率、业务检查通过率、评测裁判分数分别统计。10 个样本乘 2 个引擎共 20 次基础执行；失败后的修复重跑保留原结果，不只展示成功记录。无法执行的外部场景记为未验收，不记作通过。

## 发布门槛

1. 设计基线与代码字段、枚举和接口一致；原始两版协议已核对。
2. 前后端所有承诺操作真实可用，双引擎完成同一契约和生命周期测试。
3. 持久化、取消、故障、事件恢复与观测统计经过针对性验证。
4. 工具与全量样本有可追溯结果，外部依赖已在目标环境验证。
5. Windows 干净安装与双引擎切换按 INSTRUCTION.md 无人工执行。
6. ZIP 不含密钥、node_modules、开发日志或无关数据，包含运行所需源码、锁文件和说明。

未达到门槛只能报告实际实现和验证范围，不能把“代码完成”“本地构建通过”写成“完整交付已验收”。
