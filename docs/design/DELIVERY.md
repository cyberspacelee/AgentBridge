## 可复现检查

在 code/ 中执行：

```sh
pnpm typecheck
pnpm --filter @agentbridge/web typecheck
pnpm --filter @agentbridge/web lint
pnpm test
pnpm build
pnpm web:build
pnpm test:browser
```

原生测试按 [安装说明](../../INSTRUCTION.md#api-与验证) 分别启用。普通 pnpm test 跳过依赖主机 CLI 的六项测试，原生检查独立运行，不把 skipped 当通过。

2026-09-08 本地完整回归：后端 35 passed / 6 skipped，浏览器 44 passed / 4 skipped；前后端类型检查、lint、构建通过。六项原生检查另行启用并全部通过。

本次 Linux 原生验证使用 Pi 0.85.1、OpenCode 1.18.29、Codex 0.153.4、Grok 1.0.5。本地 HTTP 模型服务响应受控，验证的是实际 CLI 的 OpenAI 兼容协议与持久化上下文：

- Pi/OpenCode：模型发出工具调用，审批前不写文件，批准后写入实际文件，完成状态与工具记录正确；网关重启后继续上下文。
- Codex/Grok：自定义模型请求、增量文本、完成终态、网关重启、原生上下文恢复；Grok 的辅助模型调用也使用已配置模型。
- 四个 CLI：选中的 Skill 到达模型，未选中的项目 Skill 不进入模型资源列表。
- Codex/Grok 协议 fixture：工具状态、拒绝审批、自由文本提问回复、重复回复拒绝、未知请求拒绝和取消；Codex 多次模型调用用量按 Run 汇总。
- Pi MCP：使用随项目锁定的扩展和受管 mcp.json 启动原生进程；MCP 服务本身是否可连接取决于用户部署。

## 生命周期验收重点

停用立即关闭准入、取消排队而不误中断当前执行；当前执行及交互结束后停止。强停中断当前执行，停用状态阻止后台恢复。应用操作等待同 Agent 的创建、执行、隔离与恢复结束后再切换配置。未受影响 Agent 继续工作。

配置保存有乐观并发校验。新模型/资源配置应用前不影响已有进程；每次 Run 留存实际修订。被移除的历史模型不会使后续默认提交永久失败，改用当前默认模型。应用失败的 Agent 显示错误且可重试，不伪报已应用。

SQLite 历史数据库格式不匹配时拒绝启动并保留原文件；不自动删除或转换用户历史。进程恢复不重新提交已接收的旧 Run。删除任务保留用户工作目录及文件，关闭网关保留可恢复原生历史。
