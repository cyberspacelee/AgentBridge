## 复查时补齐的边界

- 页面懒加载可延迟旧组件卸载。路由 Suspense 以 pathname 为 key，使页面切换及时释放旧请求；浏览器测试曾复现旧提交将用户带回旧任务的问题，修复后通过。
- 清理采用整体期限；即使 repair 永不返回，仍尝试停止每个 adapter，并最终报告 AggregateError。服务关闭的 finally 仍关闭 Store 和日志传输。已关闭的 runtime 不再请求故障重启。
- 存储恢复测试使用 `/api/system` 确认新进程可服务，核对 instanceId 变化与 storeId 不变。未安装 CLI 时 `/health/ready` 的 503 是正确状态。

## 不按原建议修改的项目

- **2.1/T6 的“协议测试默认零覆盖”不成立。** native-protocol 默认运行；真实 CLI/模型冒烟的六个条件跳过继续保留。新增 RPC 子进程测试也默认运行。
- **2.2/X12 的“超时后产生未处理 rejection”不成立。** Promise.race 已安装拒绝处理器；多加空 catch 不会取消操作。针对实际挂起修复调用方的清理期限，没有给通用 within 虚构取消能力。
- **2.3/R1 的订阅竞态未成立。** 现有同步订阅路径有 closed 检查；X14 的背压断开是有界资源策略，客户端有事件回放与重连。
- **S1/S2/2.5 未证明存在外部输入到 SQL 标识符或 where 的路径。** 当前值参数化，调用方受控；不增加 QueryBuilder。若未来开放动态查询，必须先定义新的输入边界。
- **C1/C2/C3/X27 的并发损坏推断未成立。** 事务是明确的平坦嵌套语义；调度读取和 active 认领同步执行。保留现有约束并增加事务语义测试。
- **F1/F2/F3/F5/F10/F14/F16 等不是报告描述的错误。** 条件式 render 状态同步不会无条件循环；草稿共享有持久化用途；目录按钮在请求期间禁用；失败后的折叠操作会保留；安装检查有 checked 守卫。目录请求仍顺手补了卸载取消。
- **测试文件大、没有独立 metrics 文件、真实进程集成、受控 mock、固定采样窗口，以及类职责/重复代码属于维护或测试组织建议。** 既有测试已覆盖多项被报告为缺失的行为，不凭文件名或行数拆分类、加基类或跳过集成测试。
- **R4/R5 的映射保留须结合生命周期判断。** 关闭的原生会话由隔离/恢复/释放路径处理；hostRequest 已有 32 项上限、20 秒超时及断连清理，新增测试验证这些边界。
- **X1/X29 的启动失败和等待退出属于不同策略。** 启动失败会报错退出，不为错误配置无限重启；显式 wait 模式继续允许用户等待任务，已有 stop 模式可强制收尾。X10/X11 的开发 Origin 和内部临时端口不应当作生产页面地址使用。
- **O2 的随机密码无需跨进程持久化。** 适配器拥有并重建对应的 OpenCode 进程；没有发现“只更换客户端密码却继续连接旧进程”的正常路径。
- **短密钥不设 16 字符豁免、不缓存可变环境密钥；宿主 IPC 保留其受控父子进程边界。** 不以性能或 schema 整齐为由降低现有保护。客户端关闭请求不等于取消已被服务端接收的写入，重试仍依赖 submissionId。
